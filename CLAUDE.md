# RCX Group website

This project is a static, navigable RCX Group website built from the supplied `h-*.html` section exports and local assets. See `PRD.md` for page descriptions and design context. Edit the exports or `build_site.py`, `site.css`, and `site.js`, then run `python3 build_site.py` to rebuild the route pages. Serve the project root with `python3 -m http.server 8000` and open `http://127.0.0.1:8000/`. The generated routes include Home, About Us, Portfolio and brand pages, Join Us, Contact Us, and News.

@progress.md

The shared footer markup is `h-footer.html`, its isolated styles are in `footer.css`, and all footer navigation, company details, contacts, social links, and legal links are configured in `footer-data.json`. Empty social/legal lists are omitted until real destination URLs are provided. `build_site.py` renders this footer outside `<main>` on every generated route.

Contact and careers forms share `forms.py` markup, `forms.css` styles, and the `.rcx-form` validation/submission handler in `site.js`. Keep field names and the Web3Forms destination compatible when changing the design. Browser QA should mock submission responses rather than send live test enquiries or applications.

The 14 brand detail pages share `brand_pages.py`, `brands.css`, and `brands.js`. Content, source reference URLs, local hero/logo/gallery paths, awards, social links, and locations are in `brand-data.json`. Update that data to change a brand; run `python3 build_site.py` to regenerate. Galleries show six previews with all photos available in a keyboard-accessible native dialog. Location lists with more than two venues use accordions. Reference links found to point to other brands were omitted or replaced with address-based map searches.

Brand heroes omit the region/location line beneath the brand name; keep region and venue information in Find us. Brand pages have no secondary navigation bar. Social and website links use accessible SVG icons directly below the heading in the left column of “The brand” section, as requested by the user.

Brand description paragraphs share one 1rem font size, line height, and colour across desktop/mobile; do not give the first paragraph a larger lead style. Brand stories and Awards & recognition are always expanded, using paragraphs and a labelled section without disclosure controls. Keep all story paragraphs and award entries visible without clicks.

Brand pages also omit the “Keep exploring”/next-brand section. “Find us” uses the dark RCX purple background with white text, beige accents, and contrasting directions buttons.

Main-page hero typography is shared in `site.css`: Home, About, Portfolio, Join Us, Contact and News use 80px/5rem headings on desktop (1024px+), 45px/2.8125rem on phones (640px and below), with fluid sizing between those widths; hero paragraphs use 16px/1rem throughout. Main hero headings mix the local Gotham font (aliased as Montserrat, weight 900) with italic Georgia emphasis, including Portfolio: only “Purpose.” is serif. These selectors exclude `.brand-hero`; keep the 14 brand profiles independent.

`motion.js` and `motion.css` provide restrained fade-ups: one heading and one introductory paragraph per section, plus Portfolio/News cards. Scroll motion is 560ms/8–12px desktop and 500ms/6–8px mobile, with row staggers capped at 80ms. Heroes have a separate CSS-only, one-time load entrance on every route: headline 680ms (600ms mobile), supporting text 560ms (520ms mobile) with an 80ms delay. Text starts readable, without splitting or masks. Hero elements are excluded from the scroll controller so font readiness never cancels/restarts the entrance; reduced-motion/print show them statically. Other in-view content and long body text stay immediately readable. Fonts settle before scroll initialization; frame-throttled catch-up handles fast jumps. Keyboard/pointer access interrupts scroll entrances without overriding hover transitions. Reduced-motion/print stop the logo ticker. Navigation, forms, dialogs, disclosures, utility labels and feature-card body copy are excluded. `data-no-text-reveal` (or `data-no-word-reveal`) opts out of scroll reveals. Keep native browser scroll restoration. Verify with `output/playwright/verify-natural-motion.cjs` and `verify-hero-motion.cjs` in Chrome/WebKit.

Interaction motion uses shared 160–220ms feedback/surface tokens: gallery opening, venue/job disclosure content, form errors/status, and loading-only submit progress. Closures stay immediate and controls remain usable during entry. Touch and reduced-motion modes suppress hover movement. The logo ticker starts paused, plays only while visible, and has a Pause/Play button; no-JS/reduced-motion keep it stopped. Gallery requests preserve the current photo until the next is loaded, ignore stale responses, and announce loading/failures. `build_site.py` strips old exported reveal classes so one controller owns entrances. CSS entrances use `both` fill mode to avoid WebKit end-frame discontinuities; animationend clears their play state to restore hover behaviour. Jobs use uncapped expanded height. Verify controls with `output/playwright/verify-comfortable-ux.cjs` (form requests are mocked).

Responsive QA scripts live in `output/playwright/audit-responsive.cjs` and `verify-responsive-flows.cjs`. They use the project-local Playwright package against localhost:8123 by default; `RCX_QA_URL`, `RCX_QA_WIDTHS`, and `RCX_QA_ENGINE=webkit` configure the target. The layout audit covers all 20 routes from 320–2560px. Flow checks cover menu scrolling, validation, and all brand galleries in portrait/landscape. External embeds are excluded from these layout checks. Keep mobile statistics in a readable three-plus-two grid, navigation targets at least 44px, gallery controls within the dynamic viewport, and the native careers select styled with `appearance:none` so WebKit respects its height.

The Portfolio label links directly to `/portfolio/`; its separate 44px arrow opens only the 14 brand links. The shared header records the current destination and supports Escape/outside-click dismissal. Menus open immediately. Same-origin page changes use a 240ms native document crossfade, with a separately named stable header; links, history and scroll restoration remain native. The transition opt-in is inline in the document head to avoid a Chrome cold-stylesheet race; reduced-motion/print opt out. Preload the supplied valid Gotham font on every route. Verify with `output/playwright/verify-navigation-rhythm.cjs` in Chrome/WebKit.

For a manual Vercel deployment to the existing `rcx-website` project, run `python3 prepare_vercel.py` to create `.vercel/output`, then deploy with `vercel deploy --prebuilt --prod --skip-domain --scope jys-projects-c39d0072`. Verify the staged deployment before promoting it.
